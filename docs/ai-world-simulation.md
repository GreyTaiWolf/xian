# AI 动态世界模拟架构

## 1. 产品定位

本项目不是把现有 RPG 换成聊天框，也不是让大模型自由续写小说。

目标是：

> 玩家体验网游式升级、刷宝、副本、NPC 社交和势力活动；底层世界按照确定性规则持续推进，AI 只负责重要角色决策候选、自然对话、事件提案和叙事表现。

世界中的事实必须来自代码与存档。AI 不是数据库，也没有直接写入世界状态的权限。

## 2. 为什么基于 `xian` 扩展

`xian` 已经具备：

- TypeScript + Vite 网页工程；
- 程序化格子世界；
- 可播种随机数；
- 移动、战斗、掉落、装备、任务和存档；
- AI 天道导演、NPC 对话和模板降级；
- 移动端与桌面端 UI 基础。

因此不重写现有可玩闭环，而是在其旁边建立独立 `simulation` 内核，再逐步接入主运行时和玩家界面。

## 3. 核心原则

### 3.1 代码是唯一事实来源

程序负责：

- 世界时间；
- 人口、资源、价格；
- 生物种群；
- 势力状态；
- NPC 生死、位置、关系和知识；
- 战斗、掉落、奖励；
- 世界事件历史。

### 3.2 AI 只产生候选

统一链路：

```text
世界状态
→ 最小上下文构建
→ AI 返回结构化候选
→ Schema / 白名单 / 范围 / 引用验证
→ 规则引擎决定是否执行
→ 程序结算
→ 事件日志记录
→ AI 将已确定事实写成可读文本
```

### 3.3 无 AI 仍可运行

AI 关闭、超时、格式错误或额度不足时：

- 世界 Tick 继续；
- 市场、生态、势力继续；
- 普通 NPC 使用模板与规则；
- 动态事件使用代码模板；
- 存档、读档和离线快进不受影响。

### 3.4 所有随机可复现

相同种子、相同初始状态、相同行动序列，必须得到相同结果。

每个子系统使用从世界种子派生的独立随机流，防止某个系统增加一次随机调用后改变其他系统结果。

## 4. 分层模拟

| 层级 | 内容 | 推荐更新频率 |
|---|---|---|
| 世界层 | 国家、总人口、外交、历史趋势 | 月 / 季 / 年 |
| 地区层 | 城镇、市场、生态、商路、势力控制 | 小时 / 日 |
| 玩家附近 | 具体 NPC、怪物、采集点、动态事件 | 行动 / 分钟 |
| 重要角色层 | 自由对话、重大决策、长期记忆 | 事件触发 |

远处区域只保留统计状态；玩家到达后再展开详细个体。

## 5. WS-P0：确定性世界内核

首个测试切片是“边境行省”，包含：

- 4 个地区：青河平原、北境寒林、黑石丘陵、迷雾沼泽；
- 3 个聚落：青河镇、黑石城、北望营地；
- 3 个势力：边境领主府、四方商盟、行者公会；
- 5 个生物种群；
- 3 名重要 NPC；
- 公开、传闻、私人、秘密四种事实；
- 食物、木材、矿石、药材四类资源和市场；
- 统一世界事件日志与冷却。

这些内容是基础测试夹具，不代表最终世界观必须固定为此规模。

## 6. WS-P1：主存档与运行时接入

### 6.1 `GameState.simulation`

动态世界已成为主存档的一部分，而不是运行时临时缓存。

```text
GameState
├── world          旧玩法世界日、编年史、事件标记
├── simulation     经济、生态、势力、NPC、事实与结构化事件
├── player
├── inventory
├── equipment
└── settings
```

新世界会使用同一个世界种子同时创建格子地图和动态世界。

### 6.2 存档 v9

- 当前存档版本为 `v9`；
- v1 至 v8 继续沿原迁移链升级；
- v8→v9 会根据旧档的世界种子和世界日补建 `simulation`；
- v9 读档会再次归一，修复缺失、损坏、种子不符或时钟不一致的模拟状态；
- 导入存档与本地读档走同一条迁移和归一链；
- 未来版本存档会被拒绝，而不是按旧结构误读。

旧档没有过去的结构化经济和生态历史，因此无法凭空还原每一天。迁移时最多确定性回放 3650 个世界日；更古老的旧档在回放后对齐当前世界时钟，避免数万天重算导致浏览器阻塞，同时保留可继续游玩的状态。

### 6.3 世界日与模拟时钟

映射规则：

```text
1 个旧玩法世界日 = 24 个模拟小时
```

每日边界发生时：

1. 更新 `world.day`；
2. 将 `simulation` 只向前同步到相同世界日；
3. 执行每日经济、生态和市场 Tick；
4. 必要时执行每月势力 Tick；
5. 再交给现有天道导演处理当天叙事。

动态世界不允许倒放。模拟状态比旧世界日超前、种子不一致或损坏时，会按旧世界日重建，防止出现反因果市场和事件。

### 6.4 离线快进

离线快进现在先于 `GameRuntime` 构造执行，避免出现：

```text
Store 中角色已获得奖励
但运行时仍持有快进前角色副本
```

一次离线结算会在同一个状态提交中更新：

- 玩家经验；
- 玩家灵石；
- 旧编年史；
- `world.day`；
- 动态世界模拟状态。

保护规则：

- 单次最多应用 720 个世界日；
- 超出部分明确提示未继续结算；
- 编年史模板使用世界种子派生的随机流；
- 不调用 AI；
- 不使用 `Math.random()`；
- 同一存档时间和当前时间会得到相同结果。

## 7. 模块说明

### `types.ts`

定义完全可 JSON 序列化的世界状态：

- `WorldSimulationState`
- `RegionState`
- `SettlementState`
- `FactionState`
- `SpeciesPopulationState`
- `ImportantCharacterState`
- `WorldFact`
- `WorldEventRecord`

### `state.ts`

由种子创建初始边境行省。没有时间戳和不可复现字段，相同种子结果完全一致。

### `tick.ts`

纯规则推进：

- 小时：推进世界钟；
- 每日：生产、消费、市场、生态；
- 每月：势力财政与紧张度；
- 异常检测：粮荒、价格冲击、迁徙压力、势力紧张；
- 输出新状态和新增事件，不修改输入状态。

### `integration.ts`

负责旧玩法与动态世界的时间边界：

- 世界日映射；
- 分块推进；
- 旧档补建；
- 损坏状态归一；
- 种子校验；
- 禁止倒放；
- 超长旧档回放上限与时钟对齐。

### `offline.ts`

负责纯函数形式的离线规划：

- 现实离线时间换算；
- 720 日硬上限；
- 是否触发截断提示；
- 编年史模板的确定性选择。

### `event-log.ts`

所有世界变化统一写入事件历史：

- 严格递增序号；
- 发生时间；
- 来源系统；
- 参与者、目标；
- 因果事件引用；
- 结构化证据；
- 事件冷却；
- 容量上限。

### `ai-context.ts`

按任务构建最小上下文：

- 世界事件只拿一个地区的聚落、异常和近期相关事件；
- NPC 对话只拿该 NPC 确实知道的事实、秘密、关系和记忆；
- 不传整个世界、完整事实库或无关角色。

### `ai-boundary.ts`

AI 安全门支持三类候选：

- `WORLD_EVENT_PROPOSAL`
- `NPC_ACTION`
- `NPC_DIALOGUE_EFFECT`

验证内容包括：

- 命令类型白名单；
- 地点、角色、目标、行动、事实 ID 白名单；
- 事件引用是否存在；
- 文本与数组长度；
- 参数只能是基础类型；
- 单项关系变化 `-3..3`；
- 单次关系变化绝对值合计不超过 `6`；
- 禁止出现直接修改人口、资源、价格、货币、伤害、掉落等字段。

该模块只校验，不直接执行命令。

### `invariants.ts`

验证长时间模拟必须满足：

- 人口与资源非负；
- 价格有限且受上限保护；
- 生物食物、迁徙压力在 `0..100`；
- 关系值在 `-100..100`；
- 事件序号严格递增；
- 历史时间不倒退。

## 8. Tick 规则边界

当前规则只是稳定内核，不是最终平衡值。

### 每日经济

```text
劳动力 × 地区肥沃度 × 季节 × 确定性天气扰动
→ 资源生产
人口 × 消费系数
→ 资源消费
库存 / 目标库存 + 人口需求 + 稳定度
→ 市场供需与价格
```

### 每日生态

```text
承载量 + 食物 + 猎物 + 疾病 + 人类压力
→ 种群增减
食物不足 + 超载 + 疾病 + 人类压力
→ 迁徙压力
```

### 每月势力

```text
影响力收入 - 军事维护
→ 财政
财政不足 + 确定性波动
→ 紧张度
```

最终数值必须通过长时间模拟和玩家体验共同调参。

## 9. 自动验证

`npm run selftest` 会同时运行原玩法回归和动态世界测试。

`worldsim:selftest` 当前覆盖 26 项断言，包括：

- 相同种子生成完全一致；
- 不同种子产生差异；
- 半年推进结果可复现；
- 半年后不变量仍成立；
- 事件日志有容量上限；
- 每日 / 每月 Tick 按节拍执行；
- 推进函数不修改输入状态；
- NPC 只得到已知事实；
- 世界事件上下文不包含完整事实库；
- 合法 AI 候选通过；
- AI 直接修改人口被拒绝；
- 未授权目标被拒绝；
- 关系值突然暴增被拒绝；
- 旧世界日可确定性补建模拟；
- 模拟只向前同步；
- 种子变化会重建；
- 超长旧档不会丢失世界日；
- 离线快进存在硬上限；
- 离线编年史模板可复现且索引合法。

GitHub CI 必须依次通过：

1. `npm run typecheck`
2. `npm run selftest`
3. `npm run build`
