# 仙 —— 游戏设计文档 v0.1

> 一句话概念：一个「几何图形 + 文字 UI」画风的休闲刷宝修真世界。
> **代码是物理法则，AI 是天道** —— 世界的轨迹由 AI 周期性"导演"，但所有战斗、掉落、经济都由确定性代码结算。

---

## 0. 三大设计支柱

1. **天道 AI（世界导演）**
   世界的走向由 AI 决策驱动：势力兴衰、兽潮、秘境开启、NPC 行为、世界剧情。
   AI 以**结构化 JSON 指令**注入世界，而不是直接改数值。

2. **法则代码（确定性内核）**
   地图、战斗公式、掉落表、经济、任务状态机全部由代码结算，**seed 驱动、可复现**。
   同一个 seed + 同一串指令序列 = 同一个世界。

3. **几何文本表现（零美术成本）**
   灰度地形 + 几何图形 + 字符符号 + 文字 UI，风格统一、开发快、好扩展。

---

## 1. 核心铁律：AI 管什么、代码管什么

这是整个架构最重要的一条线，必须一开始就划清：

| 层 | 职责 | 产出 |
|---|---|---|
| AI（天道） | 决策、命名、描述、对话、叙事 | 结构化 JSON |
| 代码（法则） | 一切数值结算、状态机、地图几何 | 确定性状态 |

**铁律清单：**

- AI 只产出 JSON，不产出"效果"，只产出"意图"（意图由代码翻译成规则动作）。
- 一切数值变化必须经过确定性规则层；AI 输出进世界前先过**校验器**（schema 校验 + 数值钳制 + 引用存在性检查），非法项直接丢弃。
- **AI 可降级**：API 挂了 / 没 key / 超预算时，用模板事件库兜底，游戏照常运行。AI 是增强，不是依赖。
- **可复现**：调试时可以用同一 seed + 录制好的指令序列完整重放一个世界。

> 反面案例（要避免）：AI 说"这个玩家得到一把神剑"然后直接改存档——这就是 AI 绕过法则层，数值会崩。正确做法：AI 触发事件 `grant_quest`，代码走任务/掉落规则。

## 2. 总体架构（分层）

```
┌────────────────────────────────────────────────────┐
│ 表现层    Canvas(灰度地形/几何实体/光柱/粒子)          │
│           + DOM(面板UI/背包/日志/tooltip) + 音效      │
├────────────────────────────────────────────────────┤
│ 玩法层    移动/战斗/掉落/背包/装备/任务/经济/宗门       │
│           （纯确定性，可单元测试，与渲染解耦）          │
├────────────────────────────────────────────────────┤
│ 世界模拟层 时钟tick / 实体(城镇/宗门/妖兽/NPC/玩家)     │
│           事件队列 / 状态摘要器 / 离线快进             │
├────────────────────────────────────────────────────┤
│ 天道AI层  世界导演(周期) / 种子卡生成 / NPC对话        │
│           schema校验 / 重试 / 缓存 / token预算        │
├────────────────────────────────────────────────────┤
│ 数据层    存档(版本化JSON) / 配置表(JSON) / 生成缓存    │
└────────────────────────────────────────────────────┘
```

**关键模式：**

- **慢 AI 异步注入快世界**：世界 tick 是毫秒级，AI 调用是秒级。AI 决策通过**事件队列**异步注入，世界永远不阻塞等待 AI。
- **状态摘要器**：给 AI 的上下文永远是世界状态的**压缩摘要**（几百 token 以内），不是全量存档。
- **指令→事件翻译**：AI 指令先被翻译成规则事件（`spawn_monsters` / `change_relation` / `open_realm`），再进入确定性模拟。

## 3. 世界模型：时间、空间、实体

### 3.1 双时钟

- **现实时间**：驱动挂机收益、离线结算（存档时把离线时长模拟结算掉）。
- **世界时间**：1 世界日 = 可配置的现实分钟数（如 5 分钟）。世界日边界驱动：怪物刷新、商店补货、天道 AI 决策、编年史推进。

### 3.2 空间

- 世界 = `chunk 网格`，每个 chunk 64×64 tiles，世界大小可配置（如 128×128 chunks）。
- tile 结构：

```json
{
  "height": 0.73,          // 0=深海 1=高山
  "biome": "forest",       // sea/plain/forest/desert/snow/swamp/mountain/river
  "walkable": true,
  "decor": "♣",            // 叠加字符
  "factionOwner": "青云剑宗",
  "poi": null              // 城镇/秘境入口/资源点
}
```

### 3.3 统一实体模型

玩家只是实体的一种，平等对待 —— 这样"AI 操控世界轨迹"天然成立：

```json
{
  "id": "e_1024",
  "kind": "player|npc|monster|town|sect|realm|item",
  "pos": {"cx": 12, "cy": 8, "x": 31, "y": 40},
  "state": "idle|combat|patrol|dead",
  "data": { "...": "按 kind 而不同" }
}
```

世界轨迹 = 实体状态随世界日演化；AI 通过指令影响演化的**方向**，代码负责演化的**过程**。

### 3.4 离线快进

玩家离线后世界"还在转"（挂机网游感的核心）：

1. 载入存档时，把缺失的世界日按**确定性规则**快进：怪物重生、势力关系按速率衰减/增长、任务过期。
2. 错过的天道 AI 决策：小批量补跑（限 1~3 次，用便宜模型），或直接用模板事件兜底。
3. 快进结果生成一份"离线日志"：你闭关期间，青云剑宗攻下了北境三城……

## 4. 地图生成（重点设计）

**总思路：AI 只出"意图卡"，几何全部由 seed 确定性生成，AI 再回写"命名与叙事"。**
这样地图永远合法、永远可复现，AI 想乱来也破坏不了几何。

### 4.1 第一步：AI 生成世界种子卡（开局一次，用贵模型）

```json
{
  "seed": 882345,
  "world_name": "沧溟界",
  "world_concept": "上古仙魔大战后灵气失衡的大陆，中央有贯通南北的裂谷",
  "terrain": {
    "land_ratio": 0.42,
    "continent_style": "西北高东南低",
    "mountain_density": 0.35,
    "river_count": 4
  },
  "biomes": ["灵雾森林", "赤炎荒漠", "玄冰雪原", "幽冥沼泽"],
  "factions": [
    {"name": "青云剑宗", "alignment": "正道", "terrain_pref": "高山", "accent": "#4A8"},
    {"name": "血煞魔教", "alignment": "魔道", "terrain_pref": "沼泽", "accent": "#F44"},
    {"name": "万宝商会", "alignment": "中立", "terrain_pref": "平原", "accent": "#F84"}
  ],
  "dungeon_themes": ["仙府遗迹", "魔窟", "灵脉洞天"],
  "backstory": "……(1~3 段，成为编年史第一章)"
}
```

如果用户不想花 token 生成种子卡，也可以：代码随机 seed → AI 只负责"解读和命名"（更便宜）。

### 4.2 第二步：确定性生成管线（纯代码，`generateChunk(seed, cx, cy)`）

每层都用 seed 派生的独立噪声，**纯函数、无全局状态**，chunk 可以惰性生成、并行生成：

1. **大陆掩膜**：超大尺度低频噪声 + `land_ratio` 阈值 → 海陆。
2. **高度图**：4 个 octave 的 value noise 叠加 → 平原/丘陵/山脉。
3. **湿度图 / 温度图**：独立噪声 + 纬度梯度（北冷南热）。
4. **生物群系**：`高度 + 湿度 + 温度` 查表分类。
5. **河流**：从山脊线沿高度梯度做流场追踪，汇入大海。
6. **灰度渲染**：`height → 0..255 灰度`（深海近黑、平原中灰、雪峰近白）。
7. **势力选址**：评分函数（靠水 +、靠资源 +、远离敌对 +）× 种子卡地形偏好，选出宗门/城镇点位。
8. **路网**：城镇之间 A* 生成道路（沿低坡度走）。
9. **资源点 / 秘境入口**：按规则散布（灵气浓度 = 高度+湿度 的某个函数，高点放秘境）。
10. **妖兽分布**：生物群系对应怪物表 + **距离出生点的等级梯度**（越远越强，经典开放世界结构）。

**关键点：**

- **chunk 惰性生成**：玩家探索到哪生成到哪；因为生成是纯函数，同一个 seed 重进游戏结果一致，已生成的 chunk 也可以只存"发生过的事件"，几何永不落盘。
- **小地图**：每个 chunk 渲染时顺带生成一张低分辨率灰度快照，拼起来就是完整灰度小地图，再叠加势力色块轮廓。

### 4.3 第三步：AI 回写命名与叙事（结果缓存进字典）

- 城镇/宗门/地标 → 生成名字 + 一句描述（"霜落城——北境雪原上的边贸重镇"）。
- 世界背景故事、编年史第一章。
- 这些文本**永久缓存**，重复读取不重复调用。

### 4.4 渲染映射表（几何+文字风格规范）

| 内容 | 视觉 |
|---|---|
| 地形 | 每 tile 一个灰度方块（height→灰度） |
| 水域 | 深灰 + `≈` |
| 森林 | 灰底 + `♣` |
| 山脉 | 亮灰 + `∧` |
| 沙漠 | 中灰 + `∴` |
| 雪原 | 近白 + `*` |
| 城镇 | `▣` + 白色地名标签 |
| 宗门 | 势力色描边 `▲` + 宗名 |
| 玩家 | 主题色圆形 + 朝向小三角 |
| 怪物 | 红色系几何拼装（三角+圆），头顶等级角标 |
| 掉落物 | 稀有度色小菱形 |
| 光柱 | 稀有度色渐变矩形（刷宝爽感核心） |
| 伤害数字 | 白/黄/红浮动文字 |

**调色板原则：地形全部灰度，颜色只留给"信息"** —— 稀有度、势力、敌我。信息密度高但不花哨。

## 5. 天道 AI 世界导演（世界轨迹的核心机制）

### 5.1 循环（每个世界日边界触发）

```
1. 摘要器：压缩世界状态 → 几百 token 的 JSON 摘要
     （各势力实力/关系/领地、妖兽威胁度、玩家境界声望、进行中事件）
2. 状态哈希 → 命中缓存则复用上次决策，否则调用 LLM（默认便宜模型）
3. LLM 输出结构化指令（system prompt = 世界规则书：势力性格、世界观、schema）
4. 校验器：JSON Schema 校验 + 数值范围钳制 + 实体引用检查，非法项丢弃
5. 事件执行器：把指令翻译成确定性模拟（刷怪/改关系/开秘境/开战）
6. 编年史追加 AI 写的叙事文本 → 全服公告
```

玩家看到的结果：兽潮来了、两个宗门开战了、东南海域开了一座秘境——**世界"活"了，而且每一步都合法**。

### 5.2 指令 Schema 示例

```json
{
  "world_day": 37,
  "directives": [
    {"type": "faction_relation_change", "a": "青云剑宗", "b": "血煞魔教", "delta": -15, "reason": "边界灵矿争夺"},
    {"type": "spawn_event", "event": "beast_tide", "target_region": "北境", "power": 3},
    {"type": "open_secret_realm", "location_hint": "东南沿海", "duration_days": 5},
    {"type": "npc_action", "npc": "npc_077", "action": "travel", "target": "霜落城"}
  ],
  "chronicle_entry": "青云剑宗与血煞魔教在边界灵矿爆发冲突，北境妖兽躁动……"
}
```

### 5.3 编年史（世界感的核心资产）

- 永久追加的世界历史记录，玩家可在城镇"史官"处阅读。
- 同时作为导演 AI 的上下文——但**裁剪策略**：只带最近 N 条 + 标记为"重大"的条目，控制 token。

### 5.4 AI 调用点总清单

| 调用点 | 频率 | 模型档位 |
|---|---|---|
| 世界种子卡 + 背景故事 | 开档一次 | 贵 |
| 世界导演日常决策 | 每世界日 | 便宜 |
| 重大转折（势力更迭/世界Boss） | 偶发 | 贵 |
| 地图命名/描述 | 首次探索到 | 便宜，永久缓存 |
| NPC 对话 | 玩家主动 | 便宜，带好感记忆 |
| 任务文案 | 接任务时 | 模板+AI填空 |
| 战报/离线日志润色 | 可选 | 可关 |

**降级链**：贵模型挂了→便宜模型；AI 全挂→模板事件库随机抽取，游戏照跑。

## 6. 玩家系统（刷宝养成核心）

### 6.1 角色与属性

- 属性：生命 / 灵力（蓝） / 攻击 / 防御 / 速度 / 暴击 / 吸血 / **幸运**（掉落加成）。
- **境界**（长线养成主轴）：炼气 1-9 → 筑基 → 金丹 → 元婴 → 化神 → 渡劫 → 飞升（转生重开+永久加成）。
- 突破：材料 + 成功率 + 失败惩罚（掉小境界）；**境界压制**：跨大境界伤害 ×0.5^n，保证数值曲线平滑。

### 6.2 战斗（休闲向）

- 回合制自动战斗（挂机） + 手动施放技能。
- 秒级 tick，攻速决定出手频率；战报文字滚动。
- 副本内回合、大地图遇怪即战。

### 6.3 装备与词条

- 部位：武器 / 头 / 身 / 手 / 脚 / 饰品×2。
- 稀有度：**凡品(白) / 灵器(绿) / 法宝(蓝) / 仙器(紫) / 神器(橙) / 圣物(红)**。
- 词条：主词条固定 + 副词条随机 1~4 条，稀有度决定词条数上限。
- 养成：强化（+1~+15）、洗练（重随副词条）、套装效果。

### 6.4 背包与经济

- 暗黑式**格子制背包**，物品占格（1×1 药水 ~ 2×4 大剑），可扩展；城镇仓库、宗门仓库。
- 货币：灵石（通用） / 宗门贡献 / 势力声望。
- 交易：NPC 商店 + 拍卖行（先做 NPC 挂单，玩家间市场是后期在线版的事）。
- 掉落：权重表 × 世界等级缩放 × 幸运值；**保底计数器**（防脸黑）；首杀奖励。

### 6.5 任务

- 主线：AI 生成大纲（章节目标），代码做状态机。
- 日常/周常：纯模板（刷怪/收集/悬赏）。
- 宗门任务：贡献兑换功法、资源。

## 7. 世界内容

- **城镇**：商店 / 铁匠 / 拍卖 / 任务板 / 传送阵 / 史官（读编年史）—— 玩家的活动节点。
- **宗门**：3~7 个，各有**性格卡**（正道/魔道/中立 + 行事风格），可加入 → 贡献 → 功法/资源/专属任务；宗门战、宗门大比是世界事件。
- **妖兽**：按生物群系分布 + 距出生点等级梯度；普通/精英/首领/世界Boss 四级；兽潮是天道最常发的世界事件。
- **NPC**：性格卡 + 记忆（对玩家的好感、经历），对话按需调 AI。
- **秘境**：限时副本，由天道 AI 决定开/关，高掉率、限时——制造"错过就没了"的驱动力。
- **世界事件日历**：任意时刻存在 1~3 个进行中的世界事件（兽潮/比武/灵潮/仙府出世）。

## 8. AI 成本与稳定性控制

- **模型分级**：日常导演/NPC 用便宜模型；开局种子卡、重大转折用贵模型。
- **token 预算**：每世界日有预算上限，摘要裁剪、编年史裁剪。
- **缓存**：状态哈希复用、命名描述永久缓存、NPC 性格卡常驻。
- **重试与校验**：JSON 解析失败/校验失败 → 重试 1 次 → 丢弃该条指令。
- **玩家自带 key 模式**：很多文字游戏的做法——玩家填自己的 API key，成本归玩家，服务器只做代理转发；也可以自建小代理服务。
- **兜底**：模板事件库保证 AI 完全不可用时世界依然运转。

## 9. 技术栈与部署路线

### MVP（单机网页版，推荐起步）

- TypeScript + Canvas 2D + DOM UI，几乎零依赖。
- 噪声算法自写（value noise ~200 行，不需要引入库）。
- 存档：localStorage + JSON 导出/导入（版本号 + 迁移函数）。
- AI：OpenAI 兼容 API（DeepSeek 等）。**注意浏览器直连有 CORS 和 key 泄露问题**：
  - 开发期：Vite dev proxy 转发达成。
  - 上线：玩家自填 key（直连）+ 可选小后端代理。

### 在线网游版（后期演化）

- Node.js 服务端权威 + WebSocket；世界导演跑在服务端；存档入库。
- 玩家间交易、宗门战实时化、排行榜。

## 10. 数值平衡原则

- 一切公式**配置表驱动**：`伤害 = 攻击 × 技能倍率 × (1 - 防御/(防御+K)) × 暴击…`，改表不改码。
- 境界压制指数衰减，保证跨阶差 3 倍以上打不过、同阶可操作。
- 掉落保底计数 + 世界等级缩放，控制每小时产出期望。
- AI **永远不能直接改数值**，只能触发"产生数值变化的规则"。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 延迟 / 成本 | 异步注入 + 预算 + 缓存 + 降级模板 |
| AI 输出不稳定 | JSON Schema 校验 + 重试 + 丢弃 |
| 数值失控 | AI 不碰数值，配置表 + 单测 |
| 存档损坏/升级 | 版本号 + 迁移函数 + 导出备份 |
| CORS/密钥 | 玩家自带 key + 代理（见 §9） |

## 13. 下一步建议

1. 先做 **M0 原型**（无 AI 的可玩闭环：移动→打怪→掉落→穿装备），因为刷宝手感是最难做对的，越早验证越好。
2. 再做 **M1 地图**，因为灰度地形 + seed 生成是游戏的面子，且完全独立可先行。
3. AI 最后接，因为它是"调味料"——底层闭环好了，AI 一接就出彩。
